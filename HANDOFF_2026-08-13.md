## Current research decision

The horizontal comparison is sufficiently broad. The next primary arm should
be a vertical refinement of A1: preserve its smallest plausible causal benefit
while removing duplication, stale reinforcement, and excess cost. It must be a
new prospective arm; frozen A1 evidence and code must not be edited.

The new arm must first preserve A0's four full-success tasks, then preserve A1's
unique gain, and only then expand to all 19 tasks. Accuracy, cost, and mechanism
causality are separate claims.

### A1-R2 compact vertical revision

A1-R2 CVP is the prospective successor, not a BPR-v2 continuation. It restores
A1's already-scored `MEMORY[observed; verified; pending]` writer contract,
removes the prefix from ordinary history, discards redundant `observed`, and
retains exactly one latest `verified + pending` pair. This directly preserves
the A1 trace fact that BPR lost: after deleting two expenses, `Bike Repairs`
remained pending even when absent from the current view.

Its zero-generation preflight is `PASS` at implementation commit `ad7a39b`:
287 tests passed and the full A1 replay parsed 515/596 executed-action prefixes.
All five A1 success sentinels retained projected exposure, while rendered
memory characters fell from 531,044 to 146,925 (27.6672%). This authorizes only
a fresh receipt and the first A0 gate task; it is not a reward claim.

See `evidence/a1r2/A1R2_CVP_PREFLIGHT_SUMMARY_2026-08-14.md`.

The full prospective suite is now complete. A1-R2 scored **6/19** with reward
**6.5**, preserving all five A1 successes and adding `OsmAndMarker`. Relative
to A1 it has one paired win, zero losses, and eighteen ties. It used the same
603 model calls as A1, but 2,685,730 total tokens and 11,230.18 valid elapsed
seconds. Therefore the preregistered accuracy verdict is `PASS`, while the
strict cost verdict is `FAIL`: calls had to be fewer than 603, not equal to
603. Mechanism causality remains `NOT_ESTABLISHED_NO_MATCHED_ABLATION`; all six
successes had real reads, but activation is not a causal ablation.

One `RecipeAddMultipleRecipesFromMarkor` attempt was infrastructure-invalid
after a server shutdown and was resolved by a valid same-task replacement.
After all episodes completed, the frozen shared runner misrouted A1-R2 into an
A12-only result branch. A zero-generation evidence-layer finalizer verified
the checkpoint, run signature, episode hashes, transport counts, rewards, and
invalid-attempt linkage without modifying any episode or frozen experiment
source. See `evidence/a1r2/A1R2_CVP_SCORED_RESULT_2026-08-14.md` and its JSON
companion. The GPU server and local SSH tunnel were stopped after finalization.

### A1-R3 stale-resistant pending ledger

A1-R3 is the next prospective pure-memory arm derived directly from the A1-R2
result. It keeps the exact A1 writer contract and A1-R2 compact ledger, but an
unchanged `verified + pending` state can no longer refresh its eight-request
TTL. Two consecutive same-family actions with no material RGB progress create
one bounded past-failure fact; a visible change, state change, clear, or expiry
removes it. There are still zero extra model calls, no guard, no action
override, and no hidden UI or evaluator input.

Its zero-generation preflight is **PASS** at implementation commit
`4bbac3214c69d921912219f59f027424c921ec8e`. Real replay of the 19 A1-R2
episodes projects 282 reads and 75,609 injected characters (69.7352% of A1-R2),
prevents 130 identical-state TTL refreshes, and reads failure evidence in six
failed episodes while creating none in the six A1-R2 successes. These are
feasibility results, not reward claims.

Live generation is authorized only after a fresh server receipt. The fixed
first gate is all six A1-R2 successes, in frozen order, and must be 6/6 before
the remaining thirteen tasks are released. See
`evidence/a1r3/A1R3_SRPL_PREFLIGHT_SUMMARY_2026-08-15.md` and
`protocols/A1R3_STALE_RESISTANT_PENDING_PREREG_2026-08-15.md`.

A1-R3 subsequently failed the first live capability task and is now terminal.
`ExpenseDeleteMultiple2` received reward 0 after 34 valid single-transport
calls and 34 actions, with no infrastructure error. All 34 outputs failed the
inherited A1 MEMORY prefix contract, so the new ledger lifecycle was never
written or read. The system regression is decisive for this arm, while causal
blame cannot be assigned to the new stale/failure-memory logic because it was
inactive. See
`evidence/a1r3/A1R3_SRPL_PRIMARY_GATE_RESULT_2026-08-15.md`.

GPT Pro's first vertical design, A1-R1 BPR v1, has been audited against the full
local A1 trace. Its single-receipt causal kernel is retained, but frozen v1 is
offline-invalid: only 71.011673% of 514 historical non-none pending values fit
its 48-character/72-byte cap, while its R3 requires P95 coverage. The observed
P95 is 100 characters. A narrow, newly identified v2 revision is requested in
`GPT_PRO_A1_VERTICAL_BPR_V2_REVISION_REQUEST_2026-08-13.md`; v1 must not be
silently retuned.

Seven independent `SYS-*` design reviews now examine capabilities beyond pure
memory: milestone planning, visible-outcome verification, triggered recovery
criticism, candidate-action arbitration, budgeted trajectory monitoring,
evidence-preserving history compression, and frozen workflow retrieval. Their
entry point is `GPT_PRO_COMPOSITE_TRACKS_INDEX_2026-08-13.md`; their shared
evidence boundary is
`evidence/composite/COMPONENT_EVIDENCE_LEDGER_2026-08-13.md`.

These files are requests for independent Pro proposals. They are not A13-A19,
not preregistrations, not implemented mechanisms, and not live authorization.
Each Pro response remains an unreviewed proposal until a separate adjudication
accepts it. The seven interventions must not be silently combined. Any later
combination requires a newly frozen factorial design, source closure, and
prospective qualification.

The BPR-v2 pure-memory revision remains an independent vertical line. Neither
the seven design reviews nor future Pro responses alter BPR-v1's offline failure
or any A0-A12 formal status.
