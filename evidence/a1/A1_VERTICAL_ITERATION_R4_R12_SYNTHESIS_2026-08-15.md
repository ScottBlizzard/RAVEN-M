# A1 Vertical Iteration R4–R12 Synthesis

## Outcome

All R4–R12 prospective identities stopped on the first fixed capability task, `ExpenseDeleteMultiple2`, with reward 0. None was expanded to the remaining five gate tasks or the full 19-task suite. This is the intended fail-fast behavior, not missing data.

## What each iteration established

| Arm | Frozen change | First-task observation | Scientific reading |
|---|---|---|---|
| R4 | writer reminder | memory activated but stale page-local pending persisted | activation alone is insufficient |
| R5 | invalidate pending on material transition | removed Home-page relapse; deleted only part of target set | stale-state repair helped trajectory but not completion |
| R6 | goal requirements on every read | model retained all targets; spatial grounding became dominant failure | semantic retention was no longer the sole bottleneck |
| R7 | two-support stationary recovery | trigger did not match the material route cycle | trigger class was too narrow |
| R8 | strict ABAB route cycle | expanded repeated route did not qualify | exact-cycle detector was too narrow |
| R9 | run-length route recurrence | activated three times; behavior still did not productively diverge | recovery text did not control policy |
| R10 | static full-screen coordinate calibration | 32 reads; reward 0 | global calibration prose insufficient |
| R11 | explicit percentage-to-grid self-check | 34 reads, 10 explicit self-check thoughts, one target deleted; reward 0 | local taps improved, workflow still failed |
| R12 | consecutive ordinary-history compaction | 174 entries removed, tokens −4.37% vs R11; reward 0 | cost improved without capability gain |

## Positive knowledge, not just negative results

The experiments isolate three useful facts. First, A1's pending-item semantics can preserve intent, but it cannot make the executor obey a recovery strategy. Second, deterministic transition invalidation and history compaction reduce two concrete harms—stale carry-over and prompt inflation—even when reward remains zero. Third, explicit coordinate self-check can repair individual taps, so spatial grounding is partly instruction-responsive, but multi-item completion also needs decision-level intervention.

## Next prospective direction

Do not create R13 as another prompt-memory hot patch. The next arm should be a separately named composite system with one same-model, event-triggered repair call at the first independently defined stagnation event. It must compare specialized repair against both a no-extra-call base and a call-matched generic-reasoning control. The auxiliary call may return one bounded recovery hypothesis and one next-action principle; it may not see evaluator/UI tree/package/activity/future trace, may not override or force termination, and must be fully costed. A capability claim requires the fixed first task to pass, then the remaining five fixed gate tasks, before any 19-task release.

This direction follows the evidence: the missing variable is no longer memory availability but whether a distinct decision process can convert visible failure evidence into a different action.
