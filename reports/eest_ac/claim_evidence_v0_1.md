# EEST-AC Claim–Evidence Table v0.1

This table freezes what the first minimal smoke can and cannot support.

| Claim ID | Claim | Required evidence | Smoke decision | Forbidden overclaim |
|---|---|---|---|---|
| C1 | Typed episodic slots preserve a cross-page entity–field binding better than ordinary summary. | Paired EEST-P1 outcome, ledger audit, binding labels, and a trace showing the source hash and destination entity without task-specific code. | Signal if M-SLOTS/M-RISK retain the correct address where B3-MATCH loses or misbinds it; otherwise unsupported or refuted for this instance. | “General GUI memory improvement” from one seed. |
| C2 | GoalLedger does not invent requirements. | Every requirement maps to a task span or registered deterministic rule; corruption tests reject injected requirements; live invented-requirement rate. | Pass only at 0% locally; report the live numerator and denominator. | Treating model-proposed optional fields as task requirements. |
| C3 | Recovery entries are causally grounded in real no-effect. | Before/after semantic hashes, executed canonical action, and registry activation event. | Pass only if every entry follows a confirmed no-effect; empty registry is valid. | Creating recovery from repeated thoughts, unexecuted proposals, or elapsed time. |
| C4 | Current-screen authority prevents historical evidence from overriding the current page. | Replay/corruption tests with conflicting historical/current values plus compiler output. | Pass if current-page fields are omitted from historical context or explicitly subordinate. | A global scalar deciding authority. |
| C5 | Action-conditioned verification is selective. | Shared trigger record, gated action type/intention, all low-risk actions, and unnecessary-verification metric. | Pass if only Save/Send/Delete/Answer/Done candidates trigger M-RISK; EEST-N1 should have zero gates. | Calling a generic critic every step. |
| C6 | B3-MATCH is a fair call-schedule control. | Per-opportunity trigger logs, auxiliary-call counts, useful summary outputs, identical caps, and no padding field. | Pass if every M-RISK-eligible candidate has one B3-MATCH summary call under the same ceiling, modulo post-treatment divergence explicitly reported. | Artificial neutral padding or extra failures to equalize outcomes. |
| C7 | The minimal method improves task success. | Held-out paired wins/losses/ties across at least 12 pairs and the preregistered expansion threshold. | **Not decidable by this eight-cell smoke.** Smoke only determines implementation viability and mechanism signal. | Calling one positive-task win publishable evidence. |
| C8 | Full stale/superseded/revoked lifecycle is necessary. | Dedicated natural-hazard frequency and component ablations. | Out of scope; no lifecycle implementation in this namespace. | Reusing old H17 results as support. |
| C9 | Memory reliability is a main AndroidWorld bottleneck. | Natural memory-specific hazard rate at least 2% plus non-floor held-out results. | Stop this claim if the measured rate is below 2%. | Equating all task failures with memory failures. |

## Evidence levels

- `mechanical`: schema validation, hashes, budgets, deterministic tests.
- `episode`: raw screenshot/call/event/evaluator artifacts from one cell.
- `paired-smoke`: the two tasks compared across four arms.
- `expansion-grade`: at least 12 held-out paired instances meeting the preregistered net-win rule.

The report must state the evidence level beside every positive conclusion.
