# SYS-NAG V4: R2 + Numeric, Terminal, and Route-Recurrence Guards

This is a prospective exploratory composite controller system, not a new
memory mechanism or held-out generalization claim.

- System: `sys_r2_numeric_terminal_and_route_guard_v4`
- Experiment: `SYS_NAG_V4_R2_QWEN3VL32B_AW_HARD_S20260806_G3407_V1`
- Parent evidence: `a81d949c12726c965123f07b6c081f8aafdcbafe`
- The exact A1-R2 memory, official Qwen3-VL-32B model/revision, prompts,
  sampling, task seed 20260806, generation seed 3407, 19 instances, order, and
  native decision budgets remain fixed.

V3 validly failed RetroSavePlaylist at reward 0.5 after 50 executed actions.
Both V3 guards were silent. Its exact R2 pending item remained export-related,
but the executor repeatedly revisited Settings, Backup & Restore, Other, and
back. V4 targets that upstream L3 strategy loop under a new identity.

V4 preserves the V3 numeric and pending-terminal rules byte-for-semantics. The
new one-shot route rule reviews only the current model-visible RGB pixels, the
same request's exact injected R2 `PENDING:` value, the model-authored Action
clause, and its canonical proposed action. It records a support only when:

1. `PENDING:` is non-empty;
2. the clause contains one of the fixed uncertainty cues `explore`, `look for`,
   `alternative`, `try`, or `search for`;
3. the screen is A12 exact/near-equivalent to a stored representative under the
   same pending string;
4. the canonical action family is identical; and
5. at least one later native decision slot remains.

On the third support for one `(pending, screen, action-family)` group, V4 blocks
that proposed action without executing Android input and appends exactly:

```text
ROUTE CONSISTENCY CHECK: Under the same pending item, this visually recurring page and action have already been explored twice. Do not select that same control again. Backtrack to the nearest task-relevant item or list and inspect a different visible control or item-specific menu.
```

The next request is an ordinary executor request inside the unchanged native
budget. It is counted as a guard-induced continuation call, not as zero extra
computation. Auxiliary model calls remain zero. Terminal and route guards share
one episode-wide block cap; at most eight bounded descriptor groups are stored.
No task/app name, evaluator, reward, UI tree, OCR, activity/package, future
state, donor trace, action generation, or cross-episode state is permitted.

Before live use, a committed descriptor fixture must recompute all 19 A1-R2
episodes and the V3 Retro failure with zero generation. The six historical R2
successes must have zero route blocks; V3 Retro must route-block at the frozen
third exploratory recurrence; numeric 165→180 and V2 terminal regressions must
remain valid. Source freeze, exact config, focused tests, single transport, and
runtime bounds must pass.

Live gate order is the fixed six A1-R2 successes, then the remaining 13 without
repetition. A valid gate failure is terminal for V4 and triggers a new version,
not a rerun. Guard-silent outcomes are unattributed. A route block followed by
success is only candidate composite support until a separately registered
matched ablation. Any threshold, cue, renderer, or state change after live
generation requires V5.
