# GUI Agent 长程任务记忆机制探索：最终证据综合

## 1. 任务目标与最终收敛

课题最初的问题是：记忆机制能否提升 GUI Agent 在 AndroidWorld 长程任务中的表现。一个月的实验最终把这个问题拆成三个层次：

1. **系统层**：最终成功多少题，付出多少 calls、tokens 与时间。
2. **机制层**：记忆是否真的写入、读取并进入模型请求。
3. **归因层**：相关信息是否先于行为变化出现，并产生 evaluator 可见进展。

最终最稳健的系统结果是 R2 的 6/19。R15 没有超过 R2：固定七题只得到描述性 4/7。但 R15 的 Browser 正轨迹和后续三项回归共同促成了一个更一般的分析问题：任务所需的最小事实，究竟在哪个阶段第一次失去可用性？

## 2. 为什么首先建立可信实验基础

项目没有把 reward=0 直接当作模型失败，而是先排除基础设施与人为因素：

- 固定模型、revision、benchmark task instances、task seed 与 generation seed；
- 保存 screenshot、UI state、raw Thought/Action、memory write/read、executed action 与 evaluator；
- 将 transport failure、parser failure、action execution failure、scientific failure 分开；
- 成功时检查机制是否静默，失败时检查机制是否真正激活；
- 对正式结果使用 checkpoint、source freeze、preflight、receipt 与哈希闭包。

基线三 seed 共 57/57 个科学有效 episode，没有动作执行失败。三个 seed 的完整成功数分别为 4/19、2/19、1/19，总计 7/57。这说明单 seed 波动显著，也说明后续结果必须使用配对任务、机制激活和轨迹证据共同解释。

## 3. 实验设计：横向机制与纵向提升

### 3.1 横向：不同“记什么”

- A3：论文启发的经验记忆最小移植；存在部分协议写入，但不是完整训练系统。
- A4：工作流记忆最小移植；旧 donor 为 add，而目标为 delete，不能视为忠实 AWM 复现。
- A5：分层/图记忆最小移植；0/34 合规写入，机制未形成有效激活。
- A6：持续转移回放；0/19，重复与低变化动作增加。
- A7：透明控制；4/19，证明可以不破坏基线，但没有新增能力归因。
- A8–A12：恢复、复访、义务与动作分叉诊断；读取主要集中在失败题，成功时常静默。

这些实验并不是一组同质的“新算法竞赛”，而是一组作用不同的对照：激活失败、相关性失败、使用失败、成本失败和因果归因失败。

### 3.2 纵向：保护能力后再提升

- A0：开发 seed 基线 4/19。
- A1：简单 Action Working Memory，5/19；相对 A0 新增一题但成本显著升高。
- A2：复杂 verified-progress compound，0/19；频繁读写没有形成收益。
- R2：压缩为“已验证事实 + 未完成事项”，6/19；保留 A1 五题并新增 OsmAndMarker。
- R3–R14：多次针对首题的独立 gate 失败，没有形成比 R2 更强的完整系统。
- R15：Browser 单题成功，但固定七题 stitched diagnostic 为 4/7。

## 4. 多维比较为何比单一成功率更重要

同一实验在不同维度可以得到不同结论：

| 方法 | 结果 | 成本 | 激活 | 因果解释 |
|---|---:|---|---|---|
| A1 | 5/19 | 3.464M tokens | 515 writes / 580 reads | 有一个配对新增胜，但成本很高 |
| A2 | 0/19 | 3.170M tokens | 656/705 调用读到记忆 | 强反例：激活不等于收益 |
| R2 | 6/19 | 2.686M tokens | 六个成功均有非空读取 | 最强系统结果；仍缺 read-disabled 匹配消融 |
| A6 | 0/19 | 高动作量 | 回放持续活跃 | 信息过量可能稳定错误策略 |
| R15 | 描述性 4/7 | 六题 0.586M tokens | 六题机制全部静默 | 提供诊断线索，没有形成通用提升 |

因此，最终报告必须把“分数、成本、激活、行为分叉、因果证据”分开。机制运行只能证明实现生效；机制读取只能证明暴露；只有相关读取先于有益动作分叉并带来 evaluator 进展，才能支持机制归因。

## 5. R2：当前最强完整结果

R2 得分 6/19，相对 A1 为 1 胜、0 负、18 平；总 tokens 下降 22.5%，有效耗时下降 23.1%，calls 与 A1 同为 603。它证明轻量、压缩、非重复的记忆组织可以在不牺牲原有成功题的前提下提升系统结果。

边界同样重要：六个成功均有非空记忆读取，但没有同条件 read-disabled 消融，因此不能把全部收益强归因于记忆内容。R2 是系统级最优，不等于机制因果已经闭合。

## 6. 负结果提供了哪些边界

1. **最小移植不等于论文复现。** donor、匹配、训练、检索和完整系统依赖不能被一个外挂字段替代。
2. **更多信息可能稳定错误。** A6 的持续回放增加重复与低变化动作。
3. **读取不是恢复。** A8–A12 多次发生读取，但没有有益动作分叉。
4. **成功与机制共现不等于归因。** A7/A9/A10/A11/A12 的成功题常在机制静默时完成。
5. **串行补丁破坏可解释性。** R3–R14 的连续单题修补没有建立跨轨迹共同原因。

这些结论保留了失败数据的价值，但也必须尊重边界：旧 A4 不能否定 AWM，A5 不能否定完整 HyMEM，有限端口失败不能扩大为原论文无效。

## 7. R15 Browser：为什么它仍然重要

BrowserMultiply 需要累积五个值：1、8、10、7、2。R2、R13D、R14 与 R15 都看到了这些值，但最终分别输入 120、720、2310、1120。R15 的原始 Thought/Action 历史逐步保留了五个值并正确计算；新增组件的成熟读取为 0，因此成功不能归因于组件。

这条轨迹提示：事实可能在屏幕中出现，也可能被模型正确说出，却在 parser/history transform 中被压缩、去重或删除，导致后续记忆 writer 根本没有机会保存它。此前多数审计从“是否写入”开始，因此低估了写入之前的信息损失。

这不是“有一个成功答案后照抄”。同样的分析也可以用于失败轨迹，区分：

- 从未感知；
- 已经说出但变换后丢失；
- 已写入但未检索；
- 已检索但未改变动作；
- 已改变动作但结果仍错误。

## 8. R15 固定七题：4/7 如何改变结论

正式补跑六题结果：Expense 1、Retro 1、Calendar 0、Sports 1、Recipe 0、OsmAnd 0。加旧 Browser 成功为描述性 4/7。7/7 release gate 未通过，因此没有扩展剩余十二题。

六题中新增机制全部 0 opportunity / activation / append / read / use。三个成功只能视为组件静默成功。相对历史 R2 六题为 0 胜、3 平、3 回归，并多 42 calls、43 actions、180,350 tokens。由于不是匹配同时期消融，不能把差异归因于组件。

三项回归的故障链不同：

- **Calendar**：无效启动转移后走逐日导航，耗尽 34 步仍未保存；需要路线级恢复与预算感知。
- **Recipe**：未识别 Broccoli，重复滚动且没有无进展恢复；需要状态变化检测和重定位。
- **OsmAnd**：将 favorite/Add 误当 Marker，基于不足证据宣告完成；需要结果前证据核验。

因此，4/7 不支持“多保留历史就能普遍提升”。更准确的结论是：Browser 提供上游信息损失的清晰正例，其他任务则表明长程失败同时受导航、恢复和完成 grounding 制约。

## 9. 信息谱系：新的分析尺度

建议把完成任务所需的最小事实作为审计单位，并追踪：

`L0 pixels → L1 raw articulation → L2 parser/history transform → L3 memory write → L4 retrieval/injection → L5 action divergence → L6 evaluator outcome`

该尺度带来三个变化：

1. 分析单位从“一个组件”下沉到“一个任务事实”。
2. 负结果不再统一叫零分，而能定位最早断点。
3. 干预由断点决定：信息保真、检索、恢复策略、动作验证或终止 grounding 不能混为一谈。

信息谱系目前是由数据产生、等待进一步验证的分析框架，不是已完成的通用算法。可检验假设是：最早信息断点可能比记忆激活率更能预测何种干预有效。

## 10. 与代表性论文工作的关系

这里不声称现有论文缺少分析，也不声称信息保真首次出现。更稳妥的比较是分析尺度：

- AWM 主要研究成功工作流的归纳、检索与系统任务表现；
- HyMEM / MemGUI-Agent 主要设计结构化或混合记忆，并用系统结果与组件消融验证；
- MemGUI-Bench 主要构造 memory-centric 任务与分层能力指标；
- ATMem 使用 memory-ON/OFF 配对 rollout，估计策略层的记忆贡献。

本项目的补充视角是事实级、逐阶段归因：系统级实验回答“是否有效”，事实级谱系进一步解释“为什么在这条轨迹、这个阶段有效或失效”。二者互补，而不是替代关系。

## 11. 最终汇报应呈现的认识变化

完整故事不是“做了很多失败实验，最后 R15 偶然成功”，而是：

1. 先建立可复现、可审计的实验基础；
2. 横向和纵向比较表明，更多记忆、更多读取并不保证收益；
3. R2 给出目前最强完整系统结果，但因果仍未闭合；
4. R15 Browser 暴露写入以前的信息损失；
5. 4/7 补测阻止我们把单题解释夸大为通用系统；
6. 三项回归把长程能力进一步拆成信息保真、导航/恢复和完成验证；
7. 因而提出以最早断点选择干预的可检验问题。

## 12. Pro 复审时必须守住的证据边界

- R2 是最强完整结果；R15 不是。
- R15 的七题是 stitched 描述性诊断，不是 prospective 7/7 或完整 19 题结果。
- Browser 成功与新增组件无成熟读取，机制归因不成立。
- 六题的三项回归不是匹配消融，不能归因于组件。
- 信息谱系是分析框架与假设，不是已经验证的普遍规律。
- 不使用“论文级潜力”“重大创新”等自我评价；通过证据尺度差异、理论拆分和可证伪预测自然体现研究价值。
