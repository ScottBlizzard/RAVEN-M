### 0.2 三句话概括

- **做成了什么：** 建立了 57/57 科学有效的三 seed 基线，并在固定 19 题单 seed 配对中将 A1 的 `5/19` 改进到 R2 的 `6/19`，同时相对 A1 降低 tokens 与有效耗时且不丢失其五个成功任务。

- **边界在哪里：** A1/R2 尚无与 A0 同等的三 seed 完整评估，R2 缺 matched read-disabled 消融，R15 只形成描述性 `4/7` 且六题新机制全程零机会/零激活，因此当前只能提出并检验信息机会链框架，不能宣称稳定提升、组件因果或通用规律已经成立。

### 0.3 现有 PPT 最需要修改的三个问题

1. **开头顺序错误。** 当前先讲实验时间线和“做过什么”，再讲研究问题；应改为先抛出一个可证伪的矛盾：为什么 A2 在 `656/705` 次调用中读到记忆却得到 `0/19`，而一些成功又发生在机制静默时？

### 1.2 材料中的口径冲突与采用规则

最重要的冲突不是数字，而是 **R15 Browser 的因果解释强度**：

- 信息谱系审计材料倾向于把 R15 解释为“L1→L2 信息损失在因果上处于后续记忆阶段上游”；
- Browser 专项法证报告更严格地指出：R15 的普通历史保留五值链是直接证据，EVR 因果被反证；但失败 arms 也看到了相同 UI 值，初始截图不完全匹配，因此“先前失败由 L1→L2 丢失造成”并未被 exact-prefix 反事实建立，算术/结果推理同样是合理候选。

**本汇报采用后者的更保守口径：** R15 暴露了一个此前仪器不足的上游信息保真问题，并支持了“仅从 writer 开始审计不足”这一窄结论；它没有证明 L1→L2 丢失就是 R2/R13D/R14 失败的唯一原因。PPT 中应使用“暴露/提示/提出可检验问题”，不用“证明/定位了唯一原因”。

### 1.3 两条正交的证据轴

不能用一个“证据强/弱”标签包办所有结论。最终汇报应同时标注：

1. **系统比较强度**：任务集合、seed、模型、controller、初始状态与 generation 是否匹配；
2. **机制归因强度**：组件是否有机会、是否激活、是否进入请求、是否先于相关动作分叉、是否出现 evaluator 进展、是否存在匹配反事实。

例如，R2 对 A1 是较强的**配对系统比较**，但仍是较弱的**机制因果归因**；R15 Browser 是很强的**单轨迹直接观察**，但不是强的**跨 arm 因果比较**。

### 3.5 早期设计为什么在当时合理，为什么仍未转化为提升

| 阶段 | 当时的合理出发点 | 实验为什么没有把直觉转成稳定提升 | 今天应保留的认识 |
|---|---|---|---|
| **A1** | 长任务会忘记已完成与待确认事项，最小 episode-local pending ledger 是低复杂度起点。 | 它同时延长上下文和轨迹；有用目标与错误目标都可能被持续强化。 | “持续义务”对特定重复操作有候选价值，但必须配合状态更新与成本控制。 |

| **A3–A5** | 文献给出了主动上下文、成功工作流和结构化图记忆三种合理先验，最小移植可快速检验接口与触发条件。 | 缺训练策略、匹配 donor 或完整表示系统；有的端口未激活，有的内容不相关。 | minimal port 适合做 feasibility/activation audit，不适合当论文复现或论文有效性裁决。 |

#### 为什么组件审计和普通轨迹审计仍不足

- **组件审计**能确认代码启用、write/read 发生和文本进入请求，但若从 L3/L4 开始，就看不到事实是否从未被模型说出、是否在 parser/history transform 中丢失，或任务是否根本没有该组件的 opportunity。
- **普通轨迹审计**能发现重复点击、路线漂移和错误终止，但若分析单位仍是整条 episode，就难以判断哪一个最小事实应当在何时改变哪一个动作。
- **信息机会链新增的部分**不是“再多看几步日志”，而是同时改变三个判据：以 task-required fact 为单位；把 opportunity 放在 activation 之前；把 action divergence 与 evaluator progress 放在 read 之后。它使“模块没机会”“模块读了但没改变动作”“动作改变了但仍无进展”成为不同结论。

这个升级仍是分析框架，不是效果结论。它的价值必须由第 7 节的 matched、可推翻预测来检验。

## 4. 唯一推荐的 15 分钟故事线

### 4.1 为什么选择这一条

唯一推荐的故事是：

> **从“记忆模块有没有提分”转向“记忆何时有资格获得因果信用”：先用三 seed 基线建立证据尺；再用 A1/A2 与 A3–A12 显示激活、读取和成功会错位；随后把 R2 作为完整系统进展；最后用 R15 Browser 的无组件读取正例和六题零机会/回归，把分析单位从组件下沉到任务事实，并提出 L0–L6 信息机会链。**

它优于当前版本，因为：

- 开头是一个具体矛盾和可检验问题，不是工作量陈列；
- 每一阶段都回答上一阶段留下的问题；
- R2 与 R15 的职责严格分开，不争夺“最佳方法”位置；
- 失败实验被压缩为断点证据，而不是编号清单；
- 结尾给出证据支持的框架、边界和预测，不靠“未来会更好”收尾；
- 研究者自己的问题意识体现为：主动拒绝给 silent success 记功、拒绝把 minimal port 当论文复现、拒绝把 `4/7` 当方法得分，并把反例转成下一轮可证伪实验。

### 4.2 完整因果链

#### 第一段：先定义“什么算证据”

A0 三 seed 是 `4/19、2/19、1/19`。这说明同一系统在同一 19 题集合上也会波动；因此，后续不能只报一个成功数，必须同时问：

- 是否逐任务配对；
- 机制是否真的有机会和激活；
- 是否改变了动作；
- 是否有 evaluator 可见进展；
- 是否有匹配反事实。

**自然推出下一段：** 在这把证据尺下，简单加记忆到底发生了什么？

#### 第二段：A1→A2 产生第一个关键矛盾

A1 从 `4/19` 到 `5/19`，但 calls、tokens、时间显著增加，并出现更长错误循环。A2 试图让进度更可信、更严格，结果 `656/705` 次调用读到记忆却得到 `0/19`，还丢失 A1 的全部成功。

这说明“记忆存在、频繁读取、内容看似可信”不是一条单调改进轴；它可能改变生成分布、固化陈旧状态，或根本没有表达任务需要的集合、路由和完成证据。

**自然推出下一段：** 失败究竟发生在“没写进去”“写错了”“读了没用”还是“任务本来就不是记忆瓶颈”？

#### 第三段：A3–A12 把零分拆成不同断点

横向实验不是算法竞赛，而是断点探针：

- A5：写入前未激活；
- A4：内容进入系统但语义不相关；
- A3/A8/A10–A12：有读取，仍无 productive divergence；
- A6：过度活跃，重复行为增加；
- A7/A9/A10–A12：成功时机制静默。

这批负结果最重要的贡献是：**最终分数和 read count 都不足以识别机制状态。**

**自然推出下一段：** 在这些约束下，是否还能得到一个不破坏已有能力、且更节省上下文的完整系统进展？

#### 第四段：R2 是系统层的可靠进展

R2 用 compact verified facts + pending obligations 压缩 A1，得到 `6/19`，相对 A1 `1w/0l/18t`；tokens `-22.5%`、time `-23.1%`，calls 不变。它保留 A1 五个成功并新增 OsmAndMarker。

这是全项目最稳妥的完整系统结果，但它只建立“R2 系统身份在该 seed 上更好”；没有 matched read-disabled，不能证明是哪段记忆文本导致新增成功。

**自然推出下一段：** 即使系统结果提高，我们仍然不知道哪条信息真正进入了哪次决策。怎样把归因单位从“整个模块”缩小？

#### 第五段：R15 Browser 造成证据冲突

R15 Browser 中，普通历史逐步保留 `1,8,10,7,2`，模型计算并输入 `1120`；成熟 EVR read 为 0。于是：

- 成功是真实的；
- 新组件没有资格获得信用；
- 先前从 writer/read 开始的审计不足，因为任务事实也可能通过普通历史进入决策；
- 失败 arms 虽看到同一五值 UI，却算出不同答案，因此信息保真与答案合成都必须被观测。

**自然推出下一段：** 这是一个有价值的单例，但它能否推广到其他 R2 成功题和其他失败类型？

#### 第六段：六题 continuation 限制 R15 的作用域

六题得到 `3/6`，与 Browser 拼接为描述性 `4/7`；六题 EVR 从 opportunity 到 use 全为 0。三个成功是 silent success，三个回归也不能归因于 EVR 内容。相对历史 R2 是 `0w/3t/3r`、`+180,350 tokens`，且并非 matched comparison。

Calendar、Recipe、Osm 的失败链又分别指向路由/预算、识别/无进展恢复、完成 evidence/grounding。于是 R15 的价值不是“效果一般”，而是明确否定了“Browser 的信息问题可直接概括所有长程失败”。

**自然推出下一段：** 需要一个能够同时容纳 Browser 正例、零机会任务、silent success 和 active failure 的共同分析单位。

#### 第七段：提出信息机会链与因果信用规则

以“完成任务所需的最小事实”为单位追踪：

`L0 pixels → L1 raw articulation → L2 parser/history transform → L3 write → L4 retrieval/injection → L5 action divergence → L6 evaluator outcome`

对于一个特定记忆机制，还应记录：

`opportunity → activation → append → read → use → action divergence → evaluator progress`

只要链条中某个前置环节为 0，就不能把最终结果归因于该机制；即使链条闭合，强因果仍需 matched counterfactual。

**自然推出结论：** R2 告诉我们系统可以进步；A 系列和 R15 告诉我们如何避免把进步、失败和模块运行错误地混为一谈。下一轮实验应根据最早断点选择干预，而不是再增加一个通用记忆字段。

## 7. R15 的最佳学术叙述

### 7.1 可直接用于汇报的严谨叙述

> R15 不应作为“更强记忆方法”呈现。BrowserMultiply 的成功轨迹直接显示：五个数值 `1,8,10,7,2` 被普通模型历史逐步保留，模型最终计算并输入 `1120`；但 R15 特有 EVR 在成熟阶段没有进入任何模型请求，因此不能获得成功信用。随后六题 continuation 得到 `3/6`，与 Browser 拼接仅为描述性 `4/7`；六题中 EVR 从 opportunity 到 use 全为 0，并出现三项相对历史 R2 的回归。因而 R15 真正改变的不是“最佳方法是谁”，而是审计顺序：在评价模块前，先验证任务所需事实是否出现、是否在历史变换中保持可用、机制是否有工作机会，以及它是否先于有益动作分叉。

### 7.2 “R15 之前—证据冲突—R15 之后”的认识变化

| 维度 | R15 之前的默认问题 | R15 带来的证据冲突 | R15 之后的更严谨问题 |
|---|---|---|---|
| 分析单位 | 一个 memory arm 是否提高最终分数 | Browser 成功但 R15 专属 EVR read=0 | 哪一条任务事实沿 L0–L6 在何处首次失去可用性？ |
| 激活判断 | 有 write/read 就说明机制进入工作 | A8–A12 有 read 无 productive divergence；R15 成功无 read | 机制是否有 opportunity、相关 read、动作分叉和 evaluator 进展？ |
| 成功归因 | 成功发生在 arm 中，可把部分信用给 arm | Browser 与三项 continuation success 都是 component-silent/unattributed | 没有相关信息进入请求，就不给组件记功；共现不是因果。 |
| 失败解释 | 长程失败可能统一由“忘记”造成 | Calendar/Recipe/Osm 分别是 route/budget、recognition/recovery、completion grounding | 先分类任务瓶颈，再决定用记忆、路由、恢复还是验证干预。 |
| 泛化判断 | Browser 的数值保留可能扩展到其他题 | 六题机制 opportunity 全 0，且 `0w/3t/3r` | 目标语法的作用域必须由 opportunity 先定义，不能按任务数泛化。 |
| 下一步设计 | 继续加字段、触发器或 parser 补丁 | R3–R15 的串行特例修补难以形成匹配归因 | 先做最小事实的 exact-prefix/matched intervention，再决定是否建模块。 |

### 7.3 对 `4/7`、零激活与旧能力退化的统一解释

`4/7` 应拆解，而不是平均：

- **Browser 的 1 个成功：** 真实成功；普通历史保留五值链；EVR read=0；属于“成功但新组件无信用”。
- **六题中的 3 个成功：** Expense、Retro、Sports 均是 component-silent success；只能说明 R15 运行身份在这些轨迹上没有阻止成功，不能说明 EVR 有效。
- **六题中的 3 个回归：** Calendar、Recipe、Osm 相对历史 R2 失败，但 EVR 无 opportunity、无 prompt exposure；因此不能把退化归于 EVR 内容。
- **总体作用域：** 目标语法只覆盖 collection-arithmetic 类机会，而六题都在语法外。零机会本身就是 gate 结果：它限制机制适用范围，却没有评价机制在适用任务上的效果。
- **成本与旧能力：** 六题相对历史 R2 多 `42` calls、`43` actions、`180,350` tokens，说明 stitched 运行轨迹更长；但起始状态、路线和 temperature 不匹配。现有证据无法区分随机生成、环境状态、controller/提示身份差异、长轨迹导致的上下文膨胀或其他非 EVR 因素。
- **可排除的一点：** 因为 EVR 内容从未进入请求，不能说“EVR 记忆文本直接毒化了这三题”。
- **不能排除的一点：** R15 整体运行身份与历史 R2 不完全相同；在没有同时期 matched control 前，任何具体回归原因都只能是假设。

所以，`4/7` 既不是“效果不错”，也不是“效果一般”。它是一个**诊断组合**：一个无组件读取的正例、三个静默成功、三个零机会回归。它把“得分”拆成了作用域、激活与归因三个问题。

### 7.4 三条可证伪预测

#### 预测一：任务相关事实保留，而非上下文长度本身，决定 Browser 决策

在完全相同的 Browser step-17 screenshot、system prompt、model revision 和 decoding 下，构造三臂 exact-prefix 反事实：

1. R2 变换后的历史；
2. R2 历史 + 真实五值事实；
3. R2 历史 + 等长但打乱/无关的数值文本。

**预测：** 第 2 臂产生 `1120` 或正确提交动作的比例显著高于第 1、3 臂。如果第 3 臂同样提升，说明关键可能是一般上下文/随机生成而非任务相关事实；如果三臂无差异，当前“上游事实保真重要”的解释被削弱。

#### 预测二：Browser 型干预不会普遍修复 Calendar/Recipe/Osm

在 matched 配置下，仅增加“保留原始数值/事实片段”的干预：

- Browser 应更可能出现正确答案合成；
- Calendar、Recipe、Osm 不应稳定改善，因为其已观察瓶颈分别在 route/budget、recognition/recovery、completion grounding。

如果相同干预同时稳定修复后三类任务，则当前任务瓶颈分类过窄，需要重新审计共同因素。

#### 预测三：最早断点标签比 read count 更能预测干预响应

预注册一组任务，在不知道结果的情况下先标注最早断点 `L0–L6`，再为每类断点选择匹配干预。比较两种预测器：

- 仅用 memory read count；
- 用最早断点 + task-required fact 类型。

**预测：** 后者对“哪类干预产生有益动作分叉”的预测更准。如果 read count 同样或更准，信息机会链作为设计准则的价值被削弱。

### 7.5 “为什么之前没有这样分析？”的最佳回答

> 前期并不是完全没有做机制审计，而是审计起点主要在 writer、retrieval 和 follow-action，因为当时合理的假设是：长程失败来自记忆表示和检索不足。A5 的未写入、A6 的过度回放、A8–A12 的“有读无分叉”和多次 silent success 逐步显示，仅从 L3/L4 开始仍然解释不了结果。R15 Browser 又提供了一个特别清楚的反例：成功信息走普通历史，而新组件完全没读，这才让“写入之前的信息保真”和“任务事实级单位”成为必须显式测量的问题。回头看，L0–L2 的哈希与变换审计确实应该更早加入；这不是把遗漏包装成成果，而是说明测量框架是被一系列反例逼着扩展的。现在的责任是用 exact-prefix 干预验证它，而不是把它直接宣布为定律。

> 我不把本项目定位成“比这些工作更强的记忆模块”。AWM、HyMEM、MemGUI-Agent、MemGUI-Bench 和 ATMem 分别在工作流、结构化记忆、主动上下文、benchmark 与策略级配对归因上解决了更完整的问题。我这组实验最有辨识度的部分，是在一个冻结 GUI agent 系统里，把分析单位下沉到一条任务事实，追踪它是否有机会、是否进入请求、是否先于动作分叉、是否带来 evaluator 进展。这个尺度可以补充系统级结果，但当前仍需要 matched intervention 才能从诊断框架走向稳健因果结论。

## 10. 可直接替换进 PPT 的关键文案

### 10.1 封面

**主标题：**

> GUI Agent 长程任务中的记忆：从系统增益到信息归因

**副标题：**

> 一条配对系统进展，以及一次由反例推动的分析尺度转折

### 10.2 研究问题页三行文字

> 同一记忆机制可以频繁读写，却不产生任何有益动作。  
> 同一个成功也可能发生在机制完全静默时。  
> **研究问题：什么信息、在什么任务上、通过哪一阶段，才会产生可验证的有益动作分叉？**

### 10.3 R2 结论页核心文案

> **固定 19 题单 seed 配对：A1 `5/19` → R2 `6/19`，`1 win / 0 loss / 18 ties`。**  
> Tokens `-22.5%`，有效耗时 `-23.1%`，calls 保持 `603`。  
> **这是当前最可靠的完整系统进展；没有 matched read-disabled 消融，因此机制因果仍未闭合。**

### 10.4 R15 转折页核心文案

> Browser 成功时，普通历史保留了 `1,8,10,7,2→1120`，但成熟 EVR read 为 `0`。  
> 扩展六题中，EVR 从 opportunity 到 use 全为 `0`，并出现三项历史回归。  
> **R15 改变的不是“最佳方法”，而是审计顺序：先问任务信息是否有机会进入决策，再问模块是否有效。**

### 10.5 最终结论页三点

1. **系统结果：** R2 在冻结单 seed 的完整 19 题上达到 `6/19`，相对 A1 `1w/0l/18t`，并降低 token/time；这是系统级配对进展，不是稳定性或组件因果证明。
2. **证据边界：** A2 与 A3–A12 说明未激活、不相关、读后不分叉、过度活跃和静默成功会被同一个最终分数掩盖；R15 的 `4/7` 进一步限制了单题解释的作用域。
3. **分析框架：** 下一步以任务所需最小事实为单位追踪 L0–L6，并只在相关信息先于有益动作分叉且获得 matched 反事实支持时授予机制信用。

### 10.6 最后一页收束句

> **这项工作的收束不是“找到最强记忆”，而是把下一次实验变成一个可证伪的问题：哪条任务事实，在哪一层失去可用性，什么干预能让它产生有益动作分叉？**

## 11. 答辩风险与回答

### Q1. 为什么 A0 有三个 seed，却没有给 A1/R2 同等三 seed？

**回答：** A0 的三 seed 是我用来建立系统波动和实验可信度的基线；A1 到 R2 的阶段采用固定 seed 逐任务配对，是为了在有限算力和时间下快速做机制筛选与保护性迭代。这能支持“在该冻结 seed 上，R2 对 A1 是 1 胜 0 负 18 平”，但不能支持稳定性结论。最终汇报会把这一限制放在主页面，而不是藏到问答；下一步真正要升级结论等级，优先级就是对 A1/R2 做预注册多 seed 复验。

### Q2. 单 seed 的 `6/19` 是否可能只是随机波动？

**回答：** 可能，所以我不把它叫稳定提升。它比单纯的 6 这个数字更强的地方，是与 A1 在同一 19 题上的逐任务配对：保留五个成功、只新增 OsmAndMarker，得到 `1w/0l/18t`，同时 token/time 下降；但 A0 的 `4/2/1` 已经说明 seed 波动真实存在。最准确的结论是“单 seed 配对系统进展”，而不是“泛化已证明”。

### Q3. 为什么不直接对 `6/19` 做显著性检验或置信区间？

**回答：** 19 个任务并非同分布独立样本，且这里只是一个 task/generation seed 的配对集合，简单套二项分布会给出虚假的精确感。更有意义的是报告逐任务 win/tie/loss、三 seed 基线波动、成本和机制证据，并承认后续多 seed 缺失。统计稳定性需要新的预注册重复，而不是在现有单 seed 上计算一个看似漂亮的 p 值。

### Q4. 大量 A 系列没有提分，为什么仍有研究价值？

**回答：** 前提是不能把失败方法按编号堆起来。A5 告诉我机制根本没写入，A4 告诉我检索内容语义不相关，A8–A12 告诉我读入后没有 productive divergence，A6 告诉我过度回放可能稳定错误，A7/A9 又显示成功时机制可以静默。这些结果排除的是不同的简单解释，并直接决定下一次应修 writer、relevance、policy recovery 还是完成验证；它们不用于宣称原论文无效。

### Q5. A2 `0/19` 是否说明工作记忆方向本身不成立？

**回答：** 不能。A2 是“可信最近进度 + 严格格式 + 窄成本守卫”的复合系统，它确实频繁激活，但只保留一条最近进度，难以表达集合状态，也覆盖不了跨页面路线漂移。它建立的窄结论是：在这个实现和 seed 上，更频繁、更严格的最近进度不足以提升，且会破坏原本成功轨迹；这反而帮助 R2 转向更紧凑的 verified facts + pending obligations。

### Q6. R2 六个成功都有 read，为什么不能说记忆有效？

**回答：** 因为 read 与成功只是共现。要把新增 OsmAndMarker 胜利归因于某段记忆文本，需要同一状态、同一其他上下文下的 read-enabled/read-disabled 或内容删除反事实，并观察相关动作分叉。现有 R2 足以建立系统身份在该 seed 上更好的配对结果，不足以把系统增益拆给内部组件；这正是我把系统层和机制层分开的原因。

### Q7. 你说 R2 更省成本，但预注册 cost verdict 为什么是 FAIL？

**回答：** 预注册门是合取条件：tokens、时间和 calls 都必须下降。R2 对 A1 的 tokens 下降 22.5%、有效耗时下降 23.1%，但 calls 都是 603，所以严格 verdict 是 FAIL。PPT 可以诚实说“token/time 更低”，不能说“全面通过成本门”或“调用更少”；这个细节反而体现我没有事后改判据。

### Q8. R15 只有 `4/7`，为什么还要重点讲？

**回答：** 因为我不把 `4/7` 当方法性能。它由一个 Browser sealed success、三个组件静默成功和三个零机会回归组成，且剩余 12 题未跑。它的价值是把一个系统分数拆成作用域、激活和归因：Browser 告诉我成功信息可以走普通历史，六题则告诉我这个 EVR 语法对其他瓶颈根本没有工作机会，因此阻止了从一个正例外推通用方法。

### Q9. 新组件根本没读，R15 与机制创新还有什么关系？

**回答：** 对 EVR 机制效果本身，当前没有正证据，应该明确说 NO-GO。R15 的研究价值不来自新组件“创新成功”，而来自一个自然的归因反例：成功发生了，但组件没有进入请求，所以我们必须拒绝给它记功，并把审计单位下沉到任务事实和普通历史变换。这个分析尺度仍是待验证框架，不能替代真正的机制实验。

### Q10. 为什么直到最后才形成信息机会链分析？

**回答：** 前期已经在审计 write、read 和 follow-action，只是起点默认在 L3/L4，因为当时问题被定义为记忆表示与检索。A5 的未写入、A8–A12 的“有读无分叉”、多次 silent success 逐渐显示这个起点不够；R15 Browser 又让一条成功信息经普通历史而非新组件进入决策，迫使我把 L0–L2 纳入。回看确实应更早做 raw/transformed history 哈希；现在最重要的是承认这个测量缺口并做匹配验证，而不是把晚出现的框架包装成已证明结论。

### Q11. 你是否只是根据一个成功案例事后解释？

**回答：** Browser 是提出问题的清晰案例，不足以验证框架，所以我没有停在这个案例上。六题 continuation 中的零 opportunity、A5 的未写入、A8–A12 的有读无分叉和 silent success，都能用同一链条重新表达；更关键的是我给出了会失败的预测，例如等长无关上下文如果与真实五值同样有效，就会削弱“任务相关事实保真”解释。只要有可推翻的 matched experiment，它就不只是故事化解释。

### Q12. 你是否完整复现了 AWM、HyMEM、MemGUI-Agent 等论文？

**回答：** 没有，而且汇报必须明确。A4 缺少匹配成功 donor，A5 没有完整的学习表示和图系统，A3 也没有 MemGUI-Agent 的训练数据和 Context-as-Action SFT；它们是受限的 minimal ports，用来审计接口、触发和适配条件。它们的失败只能约束“这种最小外挂实现”，不能评价原论文完整系统。

### Q13. 什么证据能证明问题真的是记忆，而不是 agent 策略或基础模型能力？

**回答：** 只有当任务所需事实先在 UI 或 raw output 中出现，随后在某个可控阶段丢失；恢复这条事实后，在 matched 条件下出现相关动作分叉和 evaluator 进展，才能较强地归因于记忆/信息可用性。Calendar、Recipe、Osm 目前更像路由、识别恢复和完成 grounding，所以我不会硬说是记忆问题。当前证据只对个别轨迹给出记忆候选，还没有把所有失败统一归因于记忆。

### Q14. Browser 的失败 arms 也看到了五个值，为什么还强调信息保真？

**回答：** 这正是我不把结论写成“L1→L2 丢失导致失败”的原因。R15 直接显示普通历史里存在可用五值链并最终算对；其他 arms 看见 UI 值却算出 120、720、2310，说明答案合成/算术同样关键。信息机会链的作用是把“看到”“保留”“使用”“算对”分开，下一步 exact-prefix 三臂反事实才能判断任务相关历史保留是否真正提高正确动作概率。

### Q15. 六题 EVR 完全静默，为什么还会比历史 R2 多 tokens、丢三题？

**回答：** 因为“EVR 内容未进入请求”只能排除直接的内容毒化，不能把整个 R15 运行身份变成与历史 R2 完全相同的反事实。两组的起始状态/路线不同，R15 generation 使用 temperature 0.7，轨迹长度也不同；额外 tokens 很可能是更长调用链的结果，但不能确定根因。没有同时期 matched control，我只报告 `0w/3t/3r` 和成本差异，不给任何具体因素做因果归责。

### Q16. 为什么 release gate 失败后不把剩余 12 题跑完？

**回答：** 预注册 gate 的作用就是阻止在一个作用域不足、归因不清的候选上继续消耗资源并产生更难解释的数据。六题已经显示 EVR 零机会、三项历史回归，而且 Browser 成功无 EVR read；此时跑剩余 12 题最多得到一个混杂的分数，不会闭合核心因果问题。停止是遵守判据，不是选择性汇报；同时必须明确因此没有 R15 的 19 题能力结论。

### Q17. 你与相关工作的差异是否只是换了一个分析术语？

**回答：** 如果只有 L0–L6 名称而没有逐 step artifact、断点判据和可证伪干预，那确实只是术语。当前项目已经用同一尺度区分了未写入、无相关机会、有读无分叉、silent success 和 completion failure，并据此改变下一步实验设计；但它还缺 matched intervention 来验证断点标签能否预测处理效果。所以我把它定位为“已实际使用的诊断框架”，不称新算法或已验证普遍方法。

### Q18. 你的“个人思考”具体体现在哪里，而不是把实验重新排版？

**回答：** 第一，主动把系统结果与组件因果拆开，哪怕这样会削弱最漂亮的 `6/19` 和 `4/7` 表述；第二，把失败实验按机会链断点而不是方法编号组织，使每个负结果都排除一个具体解释；第三，从 Browser 与六题冲突中提出能被 exact-prefix 控制推翻的预测。思想不是自称创新，而是选择什么问题、什么证据可以回答它，以及在证据不足时拒绝说什么。

### Q19. 如果再给一周，最小但信息增益最大的实验是什么？

**回答：** 我不会先跑 R15 剩余 12 题，也不会再加一个模块。最小实验是冻结 Browser step-17 的完全相同 screenshot、system prompt、model revision 和 decoding，做多 seed 三臂 prompt counterfactual：R2 变换历史、R2+真实五值、R2+等长打乱/无关数值；不增加模型调用，只比较正确 `1120`/提交动作概率和首个动作分叉。它直接区分“任务相关事实保留”“一般上下文长度”和“随机算术”，是当前故事中最关键且尚缺的反事实；若成立，再做在线 matched 验证。

### Q20. 评委最终最应该相信哪三点？

**回答：** 第一，A0 三 seed 基线有效且波动明显，这是所有结论的证据尺。第二，R2 在固定 19 题单 seed 上对 A1 是 `1w/0l/18t`，token/time 更低，但稳定性和组件因果未建立。第三，A 系列与 R15 直接显示激活、读取、动作分叉和成功不能混为一谈，因此下一步应按任务事实的最早断点做 matched intervention，而不是继续堆通用记忆字段。

## 最终裁决

现有 PPT 的基本事实边界总体谨慎，但研究叙事仍过度依赖实验时间线、方法编号和混合结果表。最强的最终版本应当主动放弃“最后一个方法最好”的常见套路，把 **R2 的系统层进展** 与 **R15 促成的事实级归因转折** 分开：前者回答“在冻结单 seed 上，系统能否不退化地更好”；后者回答“为什么得分、激活和因果信用必须分开”。

这样重构后，A0–A12、R2、R15 不再是一串实验编号，而成为一条连贯的证据链：

> **基线波动要求证据尺 → A1/A2 显示活跃记忆不保证收益 → A3–A12 定位不同断点 → R2 给出完整系统进展但留下归因缺口 → R15 Browser 暴露 silent-component positive → 六题零机会与回归限制作用域 → L0–L6 把下一步变成可证伪的匹配干预。**

这就是本次 15 分钟汇报唯一应采用的故事线。
